# Web Benchmarks

Benchmarks for the web test cases in `test-cases/web`. Every folder has one usage scenario per variant. The original
variant always loads the test-case file itself, so the benchmark measures exactly what the test case contains.

Browser scenarios use the GMT headful Firefox helper (`gmt-playwright-headful.yml`) and an nginx container serving
the repository. Every page load starts with `gmtPlaywrightResetContext()`, i.e. a fresh browser context with an
empty cache, like a first-time visitor. Loops are split into commands of at most 10 loads to stay below the
playwright IPC timeout. Compare variants by `page_loads` per joule.

| Folder | Variants | Notes |
|---|---|---|
| `fonts/` | `ttf` (test case: six local TTF files, ~4 MB), `woff2` (two Latin-subset WOFF2 files, ~55 KB), `system` (system font stack) | `make-woff2.sh` rebuilds the WOFF2 files with fonttools |
| `lazy-images/` | `eager` (test case), `lazy` (`index-lazy.html`) | Step 1: load without scrolling, step 2: load and scroll to the end. The photos in `test-cases/web/lazy-images/images` are generated by `make-images.py` (Pillow, deterministic) |
| `dom-size/` | `full` (test case: 10,000 rows, 14 elements each), `paginated` (100 rows per page, table, `DocumentFragment`) | |
| `unused-css/` | `full` (test case, 16 KB CSS), `purged` (used rules only, minified, 0.75 KB) | `build.sh` rebuilds the purged variant |
| `minify/` | `source` (test case `src/`), `minified` (esbuild `--minify --drop:console`, no source maps) | `build.sh` rebuilds `dist/` |
| `text-compression/` | `none` (test-case `nginx.conf`), `gzip-dynamic` (gzip level 5 per request), `gzip-static` (precompressed `.gz` files) | Server-side, no browser. `fetch-assets.py` fetches 4 assets 500 times each and reports `http_requests` and `transferred_kb`. `make-site.py` rebuilds `site/` |

Caveats:
- **Local network:** browser and nginx talk over a local Docker network, where transferring bytes costs almost
  nothing. The benchmarks therefore mainly show client-side and server-side CPU work. Byte savings (fonts, images,
  CSS, minification, compression) matter most on real networks and mobile radios, which this setup doesn't measure.
  For text compression, combine `transferred_kb` with a network energy model, and expect the local result to favor
  `none` or `gzip-static` over `gzip-dynamic`.
- **Small differences:** `unused-css` and `minify` save only a few KB per load. Their difference may be within
  measurement noise. That is a valid result, not a broken benchmark.
